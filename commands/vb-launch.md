# /vb-launch

You are the release manager. Gate on open bugs, generate all customer-facing artifacts, create a GitHub release, merge to main.

Branch flow: `develop` → `main`. Feature branches deleted on merge.

## Arguments

```
$ARGUMENTS
```

- `--version X.Y.Z` — override version tag (default: auto-increment from latest tag)
- `--dry-run` — run all gates and generate artifacts, do NOT create release or merge

---

## Prerequisites

```bash
gh auth status || { echo "ERROR: gh auth login first."; exit 1; }
git remote get-url origin || { echo "ERROR: No git remote."; exit 1; }
```

Read `docs/PRODUCT.md` before generating any artifact. Fetch highlights data from the Highlights Index GitHub Issue.

---

## Phase 0 — Gate Check

All gates must pass. Any failure blocks the release.

### Gate 1 — No open critical or high bugs

```bash
gh issue list --label "bug,critical" --state open --limit 10 --json number,title
gh issue list --label "bug,high"     --state open --limit 10 --json number,title
```

If any exist:
```
BLOCKED: Resolve open bugs before launch.
Critical: [N] — [list titles with issue numbers]
High:     [N] — [list titles with issue numbers]
Fix: Run /vb-simulate, or close issues with 'wontfix' label if intentionally skipping.
```
Exit. Do not proceed.

### Gate 1b — Test suite passes (blocking)

Detect test runner and run the suite:
```bash
# Node
if   grep -q '"vitest"' package.json 2>/dev/null; then pnpm exec vitest run 2>&1
elif grep -q '"jest"'   package.json 2>/dev/null; then pnpm exec jest 2>&1
else pnpm test 2>&1; fi
# Python
if test -f pyproject.toml && grep -q "pytest" pyproject.toml 2>/dev/null; then uv run pytest 2>&1; fi
```

If any tests fail:
```
BLOCKED: Test suite has failures — fix before launch.
Failed: [list failing test names]
Fix: Run /vb-review --test to regenerate or fix tests.
```
Exit. Do not proceed.

If no test files exist: warn (not blocking) — "No tests found. Run /vb-review --test to generate them."

### Gate 1c — World-class score floor (blocking)

Read the most recent `[Sim]` cycle issue body. Parse world-class scores from the UX audit summary.
Look for patterns like `World-class: N/10`, `Average: N/10`, `Score: N/10`.

If average world-class score < 7.0:
```
BLOCKED: World-class score below threshold.
Current average: [N]/10 (minimum required: 7.0/10)
Pages below 7: [list routes and scores]
Fix: Run /vb-simulate to find and fix UX issues until average reaches 7.0+
```
Exit. Do not proceed.

If no cycle data found: warn (not blocking) — "No simulation cycles found — run /vb-simulate first for a complete quality picture."

### Gate 2 — Carry bugs (warning, not blocking)

```bash
gh issue list --label "carry" --state open --limit 10 --json number,title
```
If any: list them. They appear in release notes as known issues.

### Gate 3 — Branch clean and current

```bash
git status --short
git fetch origin develop
git log HEAD..origin/develop --oneline
```
If uncommitted changes or behind remote: print diff and exit.

### Gate 4 — Highlights data exists

```bash
HIGHLIGHTS_ISSUE=$(gh issue list --search "Highlights Index" --state all --limit 1 --json number --jq '.[0].number // empty' 2>/dev/null)
HIGHLIGHTS_COMMENTS=$([ -n "$HIGHLIGHTS_ISSUE" ] && gh issue view "$HIGHLIGHTS_ISSUE" --json comments --jq '.comments | length' 2>/dev/null || echo "0")
```
If no Highlights Index issue or zero comments: warn (not blocking). GTM artifacts will be sparse.

Print gate summary:
```
LAUNCH GATES
════════════════════════════════════════════════════════
Gate 1a — Critical/high bugs:   PASS (0 open)
Gate 1b — Test suite:           [PASS | FAIL — N failing | WARNING: no tests]
Gate 1c — World-class score:    [PASS (N/10) | FAIL (N/10 < 7.0) | WARNING: no data]
Gate 2  — Carry bugs:           [PASS | WARNING: N open]
Gate 3  — Branch clean:         PASS
Gate 4  — Highlights data:      [PASS (N cycles) | WARNING: no data]
All blocking gates passed. Proceeding.
════════════════════════════════════════════════════════
```

## Phase 2 — GTM Doc Gate

Check that GTM artifacts exist and are reasonably current. These are generated by `/vb-pitch`.

```bash
MISSING_DOCS=""
for doc in docs/SALES-PLAY.md docs/PRODUCT-BROCHURE.md docs/PRODUCT-DOCS.md; do
  test -f "$doc" || MISSING_DOCS="$MISSING_DOCS $doc"
done
```

If any are missing:
```
BLOCKED: GTM docs missing. Run /vb-pitch first.
Missing: [list]
```
Exit. Do not proceed.

If all exist, check freshness — compare file modification dates against the last commit on develop:
```bash
LAST_COMMIT_DATE=$(git log -1 --format=%ct develop)
for doc in docs/SALES-PLAY.md docs/PRODUCT-BROCHURE.md docs/PRODUCT-DOCS.md; do
  DOC_DATE=$(stat -f %m "$doc" 2>/dev/null || stat -c %Y "$doc" 2>/dev/null)
  if [ "$DOC_DATE" -lt "$LAST_COMMIT_DATE" ]; then
    echo "WARNING: $doc is older than latest commit — consider running /vb-pitch to refresh"
  fi
done
```

Stale docs are a warning, not blocking.

Print:
```
GTM DOCS
  docs/SALES-PLAY.md       [present | stale]
  docs/PRODUCT-BROCHURE.md [present | stale]
  docs/PRODUCT-DOCS.md     [present | stale]
```

### docs/RELEASE-NOTES.md

Factual changelog.

Sections:
- **What's New** — features from closed `[Arch]` issues since last tag (from `gh issue list`)
- **Improvements** — UX/content improvements from closed `bug` issues
- **Bug Fixes** — from closed `bug,sim` issues: `[Severity] [module]: [description]`
- **Known Issues** — open carry bugs + open arch issues (transparent)

## Phase 3 — Create GitHub Release

```bash
git checkout develop
git pull origin develop
git tag -a [version] -m "Release [version]"
git push origin [version]

gh release create [version] \
  --title "v[version]" \
  --notes-file docs/RELEASE-NOTES.md \
  --target develop
```

If `--dry-run`: print what would be created, skip.

## Phase 5 — Close milestone + create next cycle milestone

Load milestone config:
```bash
MILESTONE_TITLE=""
MILESTONE_NUMBER=""
[ -f ".vibekit/milestone.env" ] && source .vibekit/milestone.env || true
```

**If milestone is configured:**

Close the current milestone:
```bash
if [ -n "$MILESTONE_NUMBER" ]; then
  gh api repos/{owner}/{repo}/milestones/"$MILESTONE_NUMBER" -X PATCH \
    -f state="closed" 2>/dev/null && echo "Milestone closed: ${MILESTONE_TITLE} (#${MILESTONE_NUMBER})" || true
fi
```

Create the next milestone (increment minor version — v0.1 → v0.2, v0.2 → v0.3, etc.):
```bash
if [ -n "$MILESTONE_TITLE" ]; then
  # Parse and increment minor version
  MAJOR=$(echo "$MILESTONE_TITLE" | grep -oE '^v[0-9]+' | tr -d 'v')
  MINOR=$(echo "$MILESTONE_TITLE" | grep -oE '\.[0-9]+$' | tr -d '.')
  NEXT_MINOR=$((MINOR + 1))
  NEXT_TITLE="v${MAJOR}.${NEXT_MINOR}"

  NEXT_MS_NUM=$(gh api repos/{owner}/{repo}/milestones -X POST \
    -f title="$NEXT_TITLE" \
    -f state="open" \
    -f description="Next release cycle — managed by vibekit" \
    --jq '.number' 2>/dev/null || echo "")

  if [ -n "$NEXT_MS_NUM" ]; then
    echo "MILESTONE_NUMBER=${NEXT_MS_NUM}" > .vibekit/milestone.env
    echo "MILESTONE_TITLE=${NEXT_TITLE}" >> .vibekit/milestone.env
    echo "Milestone created: ${NEXT_TITLE} (#${NEXT_MS_NUM})"
  fi
fi
```

Label remaining open arch issues with the current version label (existing behavior):
```bash
[ -n "$MILESTONE_TITLE" ] && gh issue list --label "arch" --state open --limit 50 --json number --jq '.[].number' | \
  xargs -I{} gh issue edit {} --add-label "$MILESTONE_TITLE" 2>/dev/null || true
```

## Ground Rules

1. **Gates first** — Gates 1a/1b/1c failures always block; no exceptions for bugs, failing tests, or score below 7.0
2. **Grounded artifacts** — every claim traceable to Highlights Index issue or PRODUCT.md
3. **Consistent version** — determined once in Phase 1, used everywhere
4. **Dry-run is safe** — never touches git history or creates releases
5. **Honest release notes** — include known issues; never omit carry bugs or open arch issues
6. **main is production** — merging to main is the last step, not the first
7. **Read before writing** — read PRODUCT.md and fetch Highlights Index issue before any artifact
